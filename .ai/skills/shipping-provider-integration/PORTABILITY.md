# Portability contract

Must work identically for:

```
Developer A  — macOS   — checkout at any path
Developer B  — macOS   — checkout at any other path
Developer C  — Linux   — checkout at any path
```

Nothing in this skill references an absolute filesystem path. Every path is **repository-relative**,
resolved at run time as:

```
REPO_ROOT = $(git rev-parse --show-toplevel)
<path>    = $REPO_ROOT/<repo-relative-path>
```

This is a documented discipline, not a tool-enforced one — there is no build step or pre-commit
hook in this change that scans for absolute paths. Grep new files for user-home-style absolute
paths (macOS/Linux home directories, Windows drive letters) before committing.

## Two-tier prerequisite model

This skill directory (`.ai/skills/shipping-provider-integration/`) is self-contained and fully
committed with the repository — cloning the repo gets you the whole skill. Running it against a
real provider ticket still depends on two things outside this directory:

```
┌─────────────────────────────────────────────────────────────────┐
│ Tier 1 — Uniware Java source (hard requirement, always present   │
│ in any real Uniware checkout)                                    │
│   UniwareCore/..., UniwareServices/...  — see prerequisite-check.md │
└─────────────────────────────────────────────────────────────────┘
                              +
┌─────────────────────────────────────────────────────────────────┐
│ This skill (always present once this change is committed)        │
│   .ai/skills/shipping-provider-integration/**                 │
└─────────────────────────────────────────────────────────────────┘
                              +
┌─────────────────────────────────────────────────────────────────┐
│ Developer-supplied at run time (never stored in the repo)        │
│   the ticket, its API docs, sample payloads, real credentials    │
└─────────────────────────────────────────────────────────────────┘
                              +
┌─────────────────────────────────────────────────────────────────┐
│ Optional: Reference integration path (developer-supplied only)   │
│   Provided explicitly per-run via prompt. Never auto-discovered. │
│   Prefer repository-relative paths (e.g. ./reference/).          │
│   Absolute paths accepted only when explicitly given.            │
└─────────────────────────────────────────────────────────────────┘
```

**Reference integrations are optional and never auto-discovered.** The skill never searches the
developer's machine or the repository for reference packages. If the developer explicitly provides
a reference path in their prompt, the skill may inspect it. If no path is provided, the skill
produces a useful Phase A analysis from tier 1 + bundled knowledge + the developer's own inputs,
and must say so plainly rather than silently degrading or fabricating familiarity with a reference
integration it never actually read this run.

## Relationship to tool-specific skill copies in this repository

This directory (`.ai/skills/shipping-provider-integration/`) is the **canonical, tool-agnostic**
version of this skill. Tool-specific skill directories (e.g. under `.claude/skills/` or
`.cursor/skills/`) may also exist in this repository as earlier, tool-bound copies or historical
artifacts. This skill does not read, depend on, or require any of them — it is fully self-contained
under this directory and works when any AI coding agent is explicitly pointed at it, regardless of
whether that agent has its own native skill-discovery mechanism. New tool-specific adapters, if ever
created, should point back to this directory rather than duplicating its content.

## Git / sharing strategy

| Category | Path | Commit to git? |
|---|---|---|
| This skill | `.ai/skills/shipping-provider-integration/**` | Recommended — this is what makes the skill available to a fresh clone. Not committed as part of this task (see task instructions: no `git add`, no commit performed here). |
| Uniware Java source | `UniwareCore/**`, `UniwareServices/**` | Already tracked; referenced, never copied |
| Reference package (if developer provides a path) | Developer-supplied path, e.g. `./reference/` | Never committed to this repo — supplied per-run |
| Test/scratch output | anything generated by a Phase A/B test run | Never committed — write to an isolated scratch or `/tmp` location |
| Secrets | any real token/credential | Never |
